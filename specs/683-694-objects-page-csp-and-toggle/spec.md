# Spec: extract objects-page inline scripts for the strict CSP and keep one crossing-toggle writer

- Issue: #683
- Issue: #694

## Product outcome
The objects registry page (`frontend/sea-speed/objects/index.html`) works under the strict CSP shipped by #626 (`script-src 'self' https://cdn.jsdelivr.net`, no hashes, no `unsafe-inline`): its two inline `<script>` blocks are moved verbatim into external files `frontend/sea-speed/objects/crossings.js` (crossings-layer IIFE, 56 lines) and `frontend/sea-speed/objects/registry.js` (registry script, 50 lines), referenced in the original execution order, so the registry renders and the crossings view toggle operates instead of being silently blocked by the CSP. Separately, the road page keeps exactly one writer for the crossing-line toggle: the 21-line duplicate `cxOffBtn.onclick` block in `frontend/sea-speed/road/config.js` is removed — `frontend/sea-speed/road/main.js` remains the canonical handler (error display + `drawCrossing()`), and `config.js` keeps its boot-status writes and init GET. Both new frontend files ship through the full #626 deploy module lifecycle so a release missing them fails closed before any live mutation.

## User scenarios
- A visitor opens the objects registry page under the production CSP: both external scripts load and execute (`crossings.js` before `registry.js`), the registry grid renders, and pressing the crossings view button (`#cxViewBtn`) activates the crossings layer and rewrites the URL to `?scope=water&view=crossings`, instead of the page staying dead because inline scripts violate `script-src`.
- An operator on the road page turns a crossing line off and back on: exactly one handler responds — the `road/main.js` writer with status text, error display and `drawCrossing()` — instead of `config.js`'s DOMContentLoaded-deferred simplified duplicate running later and silently overwriting it.

## Requirements
1. Issue #683 — `frontend/sea-speed/objects/index.html`: both inline `<script>` blocks move verbatim into new files `frontend/sea-speed/objects/crossings.js` (crossings-layer IIFE, 56 lines) and `frontend/sea-speed/objects/registry.js` (registry script, 50 lines); the extraction is byte-identical to the former inline blocks modulo leading/trailing whitespace (proven against base `282fe49d`). The page references them as external scripts with the execution order preserved — `crossings.js` at line 53 executes before `registry.js` at line 74.
2. Ordering safety without behaviour change: `crossings.js` reads `registryScopeKey` only inside `camFor()` at call time, and `initCxLayer` defers to `DOMContentLoaded` while `readyState` is `"loading"`, so the identifier defined by `registry.js` exists by the first call; no other token of the moved code changes.
3. The CSP stays strict: no script hashes, no `'unsafe-inline'`, no relaxation in any nginx/renderer/test fixture — the objects page satisfies `script-src 'self' https://cdn.jsdelivr.net` with external files only.
4. Issue #694 — `frontend/sea-speed/road/config.js`: the duplicate `cxOffBtn.onclick` writer block (21 lines) is removed; `config.js` keeps its boot-status writes (`cxStatus.textContent` / `cxOffBtn.textContent`) and its init GET fetch. `frontend/sea-speed/road/main.js` is untouched and remains the single canonical toggle handler.
5. Deploy contour — `deploy/vps/deploy.sh` (+53 lines): both new files follow the full #626 module lifecycle — TARGET vars (`OBJECTS_CROSSINGS_TARGET`, `OBJECTS_REGISTRY_JS_TARGET`; the JS suffix avoids collision with the API-side `OBJECTS_REGISTRY_TARGET` for `api/app/objects_registry.py`), URL vars, `release_complete -f` checks, `download_release` required loop, install-to-`TARGET_RELEASE`, bootstrap capture with file-level `<name>.absent` markers, `install_release` module-state fail-closed checks, conditional staging, `mv`-promote, and `verify_frontends` smoke serving both the success and rollback paths. Test contour: `tests/test_626_csp_no_inline_scripts.py` extended (objects page added to `HTML_PAGES`, the two new scripts to `NEW_EXTERNAL_SCRIPTS`); new `tests/test_694_single_toggle_writer.py` (exactly one file assigns `cxOffBtn.onclick` and it is `road/main.js`; `config.js` must not assign it and must keep the `cxStatus` boot write); `tests/test_unified_registry.py` JS-code assertions retargeted from the HTML to the `registry_js`/`crossings_js` class attributes (markup assertions stay on the HTML); `tests/test_vps_deploy_transaction.py` extended across release_files/setUp/env/install_live/promotion/smoke/rollback-fail-closed/bootstrap-capture.
