# Camera Live Pipeline Contract

Status: Accepted; browser security identity updated by Issue #115
Specification: specs/001-camera-live-pipeline/spec.md

## Normative requirements

1. A camera's protected browser identity MUST remain stable across source or codec changes unless the product specification explicitly changes it.
2. Live viewing MUST be independent of AI processing availability.
3. The system MUST prepare a broadly browser-compatible stream when the camera's native media is not broadly browser-compatible.
4. The browser MUST NOT be required to consume the camera's native codec directly.
5. VPS MediaMTX MUST NOT be treated as a mandatory Camera 1 browser-path dependency.
6. Camera credentials MUST NOT be embedded in browser-visible URLs or committed repository content.
7. Future camera onboarding SHOULD require only a camera identity plus protected source/relay configuration, with compatibility output generated by the system.
8. Browser camera content MUST remain inside the authenticated Sea Speed boundary defined by Issue #115.

## Current Camera 1 binding

- Protected browser identity: `/sea-speed/media/cam1/index.m3u8`
- Retired public identity: `/cams/hls/cam1/index.m3u8`
- Accepted browser media: H.264 HLS
- Browser authentication: Sea Speed Auth v1 / Authentik Forward Auth
- AI dependency: none
- Runtime media acceptance: operator-confirmed moving new Camera 1 video on 2026-08-12

Issue #115 is the explicit product change that supersedes the former public Camera 1 identity while preserving the accepted private relay and H.264 compatibility behavior.
