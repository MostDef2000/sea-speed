# Plan: road crossing period filter drives the panel and the last-crossing time becomes truthful

- Spec: specs/681-682-road-crossing-period/spec.md

## Architecture
Two fixes in the road crossing panel plus their API and test contours, no structural change. (1) Issue #681 — the period filter: `cxShowBtn.onclick` now binds `loadCrossingStats()` in `frontend/sea-speed/road/main.js`, which reads `#cxFrom`/`#cxTo`, validates `from <= to` client-side (error row + `#cxMode` «период задан неверно», no request on violation), otherwise fetches `CROSSING_SUMMARY_URL` (`/sea-speed/api/analytics/road1/crossings/summary`, main.js:11) with `date_from`/`date_to`, renders `totals` into the KPIs (`#cxStatsIn`/`#cxStatsOut`/`#cxStatsTotal`) and `by_class` (sorted by total, descending) into the table (`#cxStatsRows`), labels `#cxMode` with the applied range and flips `crossingStatsMode` to `"period"`; `renderCrossingStats` — the state-driven renderer called by the 3-second `setInterval(refresh,3000)` loop — early-returns unless the mode is `"live"`, so period numbers survive; a monotonically increasing `crossingStatsRequestSeq` discards stale responses; `#cxLiveBtn` ("Текущее") restores live mode («текущее состояние» + `refreshCrossingLast()` + `refresh()`); both date inputs default to `vlzToday()` (UTC+10). (2) Issue #682 — the browser-clock line is deleted; `api/app/analytics.py` returns the additive `last_crossing_at` (max parsed `created_at` among window-filtered records with a valid direction, `null` when none, naive timestamps as UTC, timezone-qualified ISO-8601; analytics.py:541); `renderCrossingLast` renders it in Asia/Vladivostok (ru-RU, date+time) or «Нет данных»; in live mode `refreshCrossingLast()` fetches the VLZ-today summary on boot and every 15 s solely for `#cxLast`, isolated in its own try/catch. (3) Oracles — new `tests/test_681_682_road_crossing_period.py` (`RoadCrossingPeriodTests`, 9 tests over the road page source and DOM harness) and `tests/test_line_crossing.py::SummaryLastCrossingAtTests` (5 API tests); the existing road executed twin `tests/test_frontend_contract.py` (18 road tests) pins live-mode unchanged.

## Decisions
- Client-side range validation before the request: `from > to` renders the error row and issues no request — the API would return 400 anyway (`api/app/analytics.py` rejects `date_from > date_to`), but failing fast keeps the panel state intact and avoids a pointless round trip; the API-side validation remains the backstop.
- Period mode as an explicit frontend mode flag, not a state extension: `crossingStatsMode="period"` makes the existing state-driven renderer skip the panel, so the 3-second `refresh()` loop needs no changes and live mode keeps its exact spec-044 behaviour; the mode is visibly labelled via `#cxMode` («период …» vs «текущее состояние»).
- Stale-response guard via a monotonically increasing request sequence: the panel is fed by user-triggered async fetches; without the `crossingStatsRequestSeq` guard a slow earlier response could commit over a newer one and show numbers for a range the operator did not select.
- Additive `last_crossing_at` on the existing summary instead of a new endpoint: one fetch serves KPIs, table and the last-crossing line; the field is additive, so existing consumers (the objects page `loadCrossingStats` in `frontend/sea-speed/main.js` reads only `totals`/`by_class`) are unaffected.
- Explicit Asia/Vladivostok rendering: `toLocaleString("ru-RU", {timeZone:"Asia/Vladivostok", ...})` — an emergent fix during implementation; without the explicit zone the node/browser local timezone shifts the displayed time (the #682 bug class re-entering through the fix itself).
- Spec 044 reconciliation: R4/AC-004 of `specs/044-crossing-daily-sync-registry-layer/spec.md` («Panel headline and table read state.crossings (identical numbers to the overlay)») now governs LIVE mode only; the period view is an explicit, user-initiated, visibly labelled exception (`#cxMode` shows the applied period whenever period numbers are on screen) with a return-to-live control (`#cxLiveBtn`). Live-mode behaviour is unchanged — the existing road twin (`tests/test_frontend_contract.py`, 18 road tests) stays green.
- Live-mode `#cxLast` via an isolated 15 s summary fetch rather than deriving from state: `state.crossings` carries counters but not the last crossing instant; the fetch is guarded by `crossingStatsMode === "live"` and its failure is swallowed, so it never affects state/events rendering.

## Runtime feedback
- Issue #681: on the pre-change tree `cxShowBtn.onclick` called `refresh()` — the date inputs were dead UI and the panel always showed live state counts; the period request path did not exist.
- Issue #682: the deleted browser-clock line advanced on every render regardless of crossings and showed the operator's local time instead of the event time.
- Two emergent fixes during implementation: (a) `cxFrom`/`cxTo` were initially missing from the element bindings — a ReferenceError caught by the test harness; (b) the timestamp must render with an explicit `timeZone:"Asia/Vladivostok"` — the node process's local timezone otherwise shifts the displayed time.
