# Feature Specification: Delivery Orchestrator Convergence

- Feature: 013-delivery-orchestrator-convergence
- Issue: #174
- Status: Active governance contract
- Source authorization: OUTCOME APPROVED

## Product outcome

Sea Speed has one active **Delivery Orchestrator** that retains end-to-end task context from read-only intake through implementation coordination, exact-green-head source integration and applicable separately authorized runtime acceptance. Historical Project Manager/Core Release/domain-agent paths remain compatibility/review surfaces without creating mandatory ownership handoffs.

## User scenarios

### Scenario 1 - Start new work
A new task is recovered by the Delivery Orchestrator, optionally uses Task Intake/domain lenses, receives one Outcome Contract authorization and proceeds through safe source delivery without agent handoff prompts.

### Scenario 2 - Review specialized behavior
The Delivery Orchestrator invokes API/frontend/Worker/deploy/diagnostic/governance/release lenses and receives findings while retaining the same Issue/scope/head/runtime context.

### Scenario 3 - Audit old work
Historical Issues/PRs/DR-001/002/003 and legacy authorization phrases remain readable and unchanged even though new Change Contracts accept only `OUTCOME APPROVED`.

### Scenario 4 - Work with SDD history
The historical `002-camera-preview-gallery` / `002-sdd-adoption` prefix collision remains valid; any new duplicate numeric prefix fails CI. Completed feature status is reconciled from durable evidence without rewriting old Issues.

## Requirements

- active role name MUST be Sea Speed Delivery Orchestrator;
- `project-manager.md` and `PM_BOOTSTRAP.md` MUST remain compatibility paths;
- domain contracts and `core-release.md` MUST be review lenses/checklists, not separate orchestrators;
- active task runtime MUST not require new `HANDOFF_VALIDATED` / `CORE_RELEASE_INTEGRATING` ownership-transfer states;
- new Change Contracts MUST require `OUTCOME APPROVED` and reject legacy source authorization;
- historical legacy audit records MUST remain untouched;
- active docs MUST consistently model VPS, Ubuntu Worker/relay and Windows AI Worker;
- detailed server-pull/fastest-safe execution rules MUST have one canonical owner in Delivery Policy;
- `RISK-ACTIONS-PIN-001` MUST remain in the risk register as a closed record with resolution evidence;
- SDD validator MUST grandfather only the historical 002 collision and reject new duplicate prefixes;
- evidence-backed completed SDD milestones in approved scope MUST no longer claim pending merge/runtime work;
- Auth v1 SDD MUST record accepted core fail-closed runtime boundary while accurately preserving parent Issue #115 OPEN state;
- `specs/011-worker-immutable-shared-runtime/**` and Issue #170 MUST remain outside this change;
- no production/runtime or GitHub-settings mutation is part of Stage B.

## Acceptance criteria

- exact approved branch diff contains only the 66 Issue #174 paths;
- convergence tests prove active role/lens/authorization/three-contour/risk semantics;
- SDD tests accept grandfathered 002 collision and reject a new duplicate prefix;
- Change Contract tests reject `LEGACY COMMIT APPROVED` for a new PR;
- repository/quality/SDD validators pass;
- exact final PR head passes PR Validation and Quality integration;
- expected-head merge and post-merge exact-main quality succeed;
- no production workflow is dispatched.
