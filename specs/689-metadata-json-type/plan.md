# Plan: metadata JSON type — reject non-object JSON at the analytics ingestion boundary

- Spec: specs/689-metadata-json-type/spec.md

## Architecture
One source file plus additive tests, no new module or route. `api/app/main.py` gains exactly two guards that mirror the two already present: in `post_analytics_state` (POST /api/analytics/{camera_id}/state) and in `post_analytics_event` (POST /api/analytics/{camera_id}/events), each immediately after the existing `try: <var> = json.loads(metadata)` / `except Exception: raise HTTPException(400, "metadata must be valid JSON")` block, the handler asserts `isinstance(<var>, dict)` and otherwise raises `HTTPException(status_code=400, detail="metadata must be a JSON object")`. The position is load-bearing in both directions: after the parse `except` so the malformed-JSON message is unchanged, and before the first mapping operation (`data["camera_id"] = camera_id` in the state handler, the `#587` non-finite scan and `event.get("event_id")` in the events handler) so no `TypeError`/`AttributeError` can escape. Authentication order is untouched: `require_auth(authorization)` and `analytics_identity(camera_id)` still run before the parse, so the guard is a post-auth shape check that cannot be reached without a valid worker token. `tests/test_689_metadata_json_type.py` covers the boundary end to end through the real FastAPI app and the real `require_auth` against a disposable temp `SEA_SPEED_BASE_DIR`, plus a stdlib-only line scan of `api/app/main.py` that pins all four `json.loads(metadata)` sites. Two test-infrastructure edits ship with it: the guarded-optional import list in `tests/test_run_tests_script.py` (its oracle is an exact match) and the new file's per-class `sys.modules` snapshot/restore, which replaces a module-import-time snapshot that went stale in the full battery.

## Decisions
- Mirror the two existing guards instead of introducing a shared helper: the repo already states the contract twice with the same condition, status and detail string, so copying that idiom is the smallest complete change; a helper extraction would touch the two healthy call sites and widen the diff for no behavioural gain.
- Guard after the parse `except`, not inside it: folding the type check into the `except` would work but would make one `except Exception` carry two different messages; a separate `if` keeps `metadata must be valid JSON` and `metadata must be a JSON object` distinguishable, which the tests pin on both endpoints.
- Guard before the non-finite scan in the events handler: `find_nonfinite_json_value` returns early for non-objects, so relying on it for the rejection is an accident of implementation; the explicit `isinstance` check states the contract and cannot silently regress if that helper changes.
- 400 rather than 422 for a parsed non-object: the two existing guards answer 400 and the tests accept 400 or 422, so the new sites match the established status instead of splitting the API's error vocabulary; the tests assert the 400/422 band for symmetry with any future FastAPI validation path.
- Real auth in the HTTP tests, no bypass: the class reuses the authenticated-worker fixture pattern (`SEA_SPEED_API_TOKEN` fixture value plus `Authorization: Bearer <fixture>` checked by the real `require_auth`) so AC-002's 403 case is proven against production code, not a stub.
- `TestClient(..., raise_server_exceptions=False)`: the regression is an unhandled exception; with the default the test process would re-raise and the observed 500 would be indistinguishable from a test error, so the client is built to surface the production response.
- Source guard in addition to behaviour: behaviour proves the two handlers reject non-objects, but only a source scan proves all four `json.loads(metadata)` sites carry the guard and that a future fifth site cannot land unguarded; the scan is stdlib-only so it runs even where fastapi is absent and the HTTP class skips.
- Per-class `sys.modules` snapshot: the shared battery imports sibling test modules between discovery and runtime, so a module-import-time snapshot no longer describes the world the cleanup must restore; snapshotting in `setUpClass` immediately before the app import and evicting only the names this class introduced keeps `tests/test_api_http_integration.py` green in the same process.
- Change Contract declaration is load-bearing: `api/app/main.py` is in the diff, so the autonomous policy derives `VPS deployment: REQUIRED` from the path. The PR Change Contract must therefore declare `Production impact: VPS`, `VPS deployment: REQUIRED`, `VPS execution capability: CONNECTOR`, `Ubuntu worker/relay update: NOT REQUIRED`, `Ubuntu worker execution capability: NOT APPLICABLE`, `Production safety envelope: REQUIRED` and `Operator actions expected: 0`; an undeclared or contradicting contract is rejected before merge.

## Runtime feedback
- The defect was an inconsistency, not an unknown: two of the four `json.loads(metadata)` sites already rejected a non-object, so the missing guards were visible as a code-shape gap that a source scan can pin.
- Blast radius was bounded by auth: both failing endpoints are worker-only, so the practical impact was error-rate and incident noise from client-controlled input, not an authorization weakness; the fix is still worth shipping because a 500 on valid JSON is a false server-fault signal.
- Implementation feedback: the guard must sit after the parse `except` and before the first dict operation; moving it either way either shadows the malformed-JSON message or leaves the crash in place.
- Test-harness feedback: the full battery exposed two harness problems that the focused run could not — the exact-match import-hygiene oracle rejected the three new guarded-optional imports, and the module-import-time `sys.modules` snapshot leaked a stale `api.app.*` tree into `tests/test_api_http_integration.py` (4 errors plus 1 failure). Both are fixed inside the test layer, and the observed full battery is 1439 tests OK (skipped=2).
