## Architecture

- worker_roi.py: the ROI/analytics cluster — 2 state literals + 9 defs in source order. Imports: json (diagnostic payload serialization) + time (monotonic emission gating) + cv2/numpy (polygon math + frame masking — OWNED here, unlike the wave-8 pure-Python sibling) + worker_kernel (bbox_center, env_* readers, water_recall_diagnostics_enabled) + worker_transport (fetch_remote_roi). NO datetime, NO threading/queue (no thread/queue lifecycle), NO ultralytics/av/subprocess/socket, NO requests (the road-ROI fetch lives in worker_transport), NO os/pathlib.
- Rebinder coupling: `_roi_processing_points` rebinds via `global` + assignment inside `prepare_roi_processing_frame` — the state literal, the sole rebinder and the sole reader (`detection_inside_road_roi`) all live in worker_roi.py; the worker's re-export copy is a frozen import-time snapshot, so a no-Load guard forbids any Load-context read outside worker_roi.py (an ops probe reading `worker._roi_processing_points` fails CI).
- Object-identity coupling: `_WATER_RECALL_DIAGNOSTIC_STATE` is defined ONCE in worker_roi and re-exported BY IDENTITY; every access is an in-place dict mutation or a read (nothing rebinds it — AST-guarded across all worker sources).
- hls_motion_yolo_worker_events.py: keeps select_profile_detections, draw_speed_lines_overlay, build_event, detect_vehicles, the live-envelope builders and main. Staying callers of the moved defs resolve via the fifth flat sibling re-export: `main` → prepare_roi_processing_frame/filter_detections_by_roi/maybe_emit_water_recall_diagnostics, `select_profile_detections` → filter_detections_by_roi. Import cycle safety: worker_roi imports worker_kernel + worker_transport (never the worker); the new re-export block sits after the wave-8 block, before first use.
- Gate scan model: MODULE_SOURCES extends to the EIGHT-file union (worker + media + render + transport + crossings + live + tracking + roi); REQUIRED_ENV_NAMES unchanged — the moved `MODEL_NAME` read keeps staying worker-namespace readers (origin :561/:569, new-tree :452/:460), so the union scan keeps every required env read covered and the negative pin holds.

## Decisions

- D-1: Verbatim byte-level move (assertion-guarded script, TWO regions) instead of retyping: guarantees byte- and AST-identity, verified programmatically after the write via the ROUND-TRIP reconstruction against `git show origin/main` (staying regions byte-identical INCLUDING line-1 bytes; both moved regions verbatim in worker_roi.py; 11/11 names AST-identical; moved names gone from the worker; zero duplicate defs).
- D-2: A FIFTH ImportFrom (module worker_roi) is allowed: the transport/crossings/live/tracking pins filter on their own `node.module` values, so the exactly-one assertions are per-module; the new block carries the 11 names sorted — defs AND state names, like waves 7/8: the state re-export preserves object identity (ONE diagnostic dict visible under both namespaces) and the monkeypatch/ns-injection surface.
- D-3: The rebinder-coupling pattern (wave-7 idiom) applies to `_roi_processing_points`: it REBINDS, so it moved WITH its sole rebinder and the coupling is pinned (exactly-one-global + enclosing-def + same-module + no-Load guard). `_WATER_RECALL_DIAGNOSTIC_STATE` is strictly non-rebinding (the ONLY Store access across worker/*.py is the defining literal; the emission gate mutates the dict in place) — the strict no-rebinding guard + the global-statement guard (covering the 9 defs + the diagnostic state) complete that half of the state contract.
- D-4: The recorded STAYS are forced, not stylistic: `select_profile_detections` stays because it calls the staying detect_vehicles/filter_detections_by_motion alongside the moved filter_detections_by_roi (moving it would create an import cycle); `draw_speed_lines_overlay` stays because it is a render surface (cv2) with ZERO moved-name callers and no production callers — both placements are PINNED both directions so a later drift moves them only through a conscious contract change; `detect_vehicles`/`build_event`/`build_*_live_envelope`/`main` and MotionDetector stay (model/cv2/ultralytics domain + supervision loop).
- D-5: Dead imports json/numpy REMOVED (wave-7 precedent): after the cut, `json` had zero remaining uses in the worker (sole use moved) and `numpy` likewise (all four uses moved); leaving them would trip ruff's F401 at the final head. cv2/time keep staying users and stay. `bbox_center`/`water_recall_diagnostics_enabled` (kernel block) and `fetch_remote_roi` (transport block) become/stay import-only in the worker but their blocks carry `# noqa: F401` and keep their exact alias sets (identity surface preserved).
- D-6: EOF newline ADDED to the worker file (origin 4cb8e6b's last line lacked a trailing newline): the byte-identity claim covers content lines; the trailing-newline addition is the ONLY byte delta outside the cut+insertion and is recorded as intentional in spec/plan/tasks. BOM lesson compliance (JOURNAL part-7 lesson): line-1 bytes of BOTH worker files are verified clean (no BOM) and the round-trip proof includes the leading bytes of the moved regions.
- D-7: Union-scan extension is PRE-EMPTIVE (JOURNAL:11978 owner rule — the wave-7 lesson that modules absorbing env_str/env_int calls MUST join the union scans, applied before any red battery): the media test's multi-file gate union grows 3→4 files. The NEGATIVE pin is unchanged by design — no required env name became roi-exclusive (MODEL_NAME retains staying reads at origin :561/:569, new-tree :452/:460). Dead-code candidates `road_roi_enabled`/`draw_roi_polygon` (zero production callers) are NOTED, NOT ACTED — move-only scope; recorded for a future cleanup wave.
- D-8: The gate-count transfers land in all five prior-wave suites (transport/crossings/live/tracking 7→8, media union 3→4) in the same commit as the gate script's +1 MODULE_SOURCES entry — any partial landing fails CI loudly (a suite asserting 8 before the gate ships the file, or the gate missing the shipped file the suites assert present).
