## Product outcome

Waves 1-8 extracted the pure kernel, the media/reader layer, the cv2 render/snapshot layer, the requests transport/posting layer (waves 4-5), the crossing analytics domain (wave 6), the live-publisher family (wave 7) and the tracking cluster (wave 8); the worker still mixes the ROI/analytics family with the speed-lines overlay and the supervision main loop. Wave 9 extracts the ROI/analytics family verbatim (move-only, byte-identical bodies) into NEW `worker/worker_roi.py`: the 2 state literals (`_WATER_RECALL_DIAGNOSTIC_STATE`, `_roi_processing_points`) and the 9 ROI/analytics defs (`road_roi_enabled`, `parse_road_roi_polygon`, `roi_processing_signature`, `mask_frame_to_roi`, `prepare_roi_processing_frame`, `detection_inside_road_roi`, `filter_detections_by_roi`, `maybe_emit_water_recall_diagnostics`, `draw_roi_polygon`) — TWO regions cut verbatim: Region 1 is the single water-recall state literal (origin :166 at main 4cb8e6b, with a SINGLE-blank separator around it — origin :167 — no blank-pair mechanics), Region 2 is the contiguous road-ROI processing family + water-recall diagnostics + ROI overlay (origin :370-499, closed by its trailing blank pair :500-501, leaving the standing one double-blank between `select_profile_detections` :367 and `draw_speed_lines_overlay` :502).

The wave's central mechanism is the rebinder coupling (the wave-7 idiom): `_roi_processing_points` REBINDS via `global` + assignment, so it moved WITH its sole rebinder — the ONLY `global` statement naming it across the repo worker sources sits inside `prepare_roi_processing_frame`, the sole non-literal Assign inside the SAME def, and the defining literal is top-level in the SAME module (worker_roi.py): rebinder + state are never split. Because the worker's re-export copy is a frozen import-time snapshot, a no-Load guard pins the coupling shut: NO Load-context Name read of `_roi_processing_points` exists outside worker_roi.py (the sole reader `detection_inside_road_roi` moved with it). Object-identity coupling: `_WATER_RECALL_DIAGNOSTIC_STATE` is defined ONCE in worker_roi and re-exported BY IDENTITY — it is mutated IN PLACE only (dict item assignment; the name is never rebound), so `maybe_emit_water_recall_diagnostics` and any staying reader share ONE state; it is strictly non-rebinding (the AST Store guard covers it, and no `global` statement anywhere names it or any of the 9 moved defs). The worker re-exports all 11 moved names (9 defs + 2 state) via a flat sibling ImportFrom: the supervision main loop's call sites (`prepare_roi_processing_frame`, `filter_detections_by_roi`, `maybe_emit_water_recall_diagnostics`) and the staying `select_profile_detections` (which calls the moved `filter_detections_by_roi`) keep resolving them through the worker's flat namespace.

Deliberate STAYS in the worker (recorded, not silently dropped, with forced reasons):
- `select_profile_detections` — the profile selector calls the staying `detect_vehicles` and `filter_detections_by_motion` alongside the moved `filter_detections_by_roi`; moving it would create an import cycle (worker_roi cannot import the worker). Its def placement is pinned (present in the worker, absent from worker_roi).
- `draw_speed_lines_overlay` — the speed-lines render surface: cv2 + `fetch_speed_lines_config` only, ZERO moved names, no production callers; its placement is pinned (present in the worker, absent from worker_roi).
- `detect_vehicles`, `build_road_live_envelope`/`build_water_live_envelope`, `build_event`, `main` and the MotionDetector class — the supervision main loop and its callees (cv2/numpy/ultralytics domain) are outside the ROI cut.

Convergence is fail-closed everywhere the new deployable ships: the compatibility gate's `MODULE_SOURCES` extends 7→8 (eight-file union, semantics unchanged), `validate_repo` REQUIRED_FILES, `build_exact_artifacts` (ubuntu-worker AND edge), `validate_exact_artifacts` (ubuntu-worker AND edge) and the installer's prepared-release required loop all gain `worker/worker_roi.py`, so a payload missing the flat sibling fails at CI or install — never silently at boot.

Two forced deviations from the wave-8 no-removal pattern, both pre-audited (wave-7 precedent for dead imports): (1) `import json` and `import numpy as np` become DEAD in the worker file after the cut — `json.` had exactly one use (inside `maybe_emit_water_recall_diagnostics`, moving) and `np.` exactly four (all inside moved defs) — so both top-level imports are REMOVED (cv2/time retain staying users and stay); (2) the worker file gains a trailing newline at EOF (origin 4cb8e6b ended its last line WITHOUT a newline): the byte-identity claim covers content lines, and the trailing-newline addition is the ONLY byte delta outside the cut+insertion, recorded as intentional.

Union-scan extension (pre-emptive contract transfer, per the owner rule recorded at JOURNAL:11978 — the wave-7 lesson that any module absorbing env_str/env_int calls MUST join the union scans, applied BEFORE a red battery forces it, never after): `maybe_emit_water_recall_diagnostics` reads `MODEL_NAME` (env_str) and moved into worker_roi.py, so tests/test_worker_media_module.py's multi-file gate union grows [WORKER, MEDIA, WORKER_LIVE] → [WORKER, MEDIA, WORKER_LIVE, WORKER_ROI]. The wave-7 NEGATIVE pin is unchanged by design: NO required env name became roi-exclusive — the moved `MODEL_NAME` read has staying worker-namespace readers (`build_event` origin :561, `main` origin :569; new-tree :452/:460), so the [WORKER, MEDIA] two-file union still misses exactly the same API env pair as before.

Dead-code candidates NOTED, NOT ACTED (move-only scope): `road_roi_enabled` and `draw_roi_polygon` have ZERO production callers repo-wide (import-only in the worker re-export; the only references are test pins, and tests/test_worker_rtsp_media_security.py asserts `draw_roi_polygon` is NOT called in `main()` — which stays true). They moved verbatim with their family; a future cleanup wave may delete them, but this wave changes no body and drops no name.
