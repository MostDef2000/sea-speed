# Plan: login popup replaces the full-page auth redirect

- Spec: specs/710-login-popup/spec.md

## Architecture
One new public helper plus its wiring, retargeting and deploy contour, no structural change. (1) The helper: `frontend/sea-speed/login-popup.js` (new) is an IIFE exposing `window.SeaSpeedAuth = {openLogin, showOverlay, loginUrl}`; it deploys to the PUBLIC web root as `/login-popup.js` (mirroring `unavailable.js`) because the `/sea-speed/` shell is auth-protected and its HTML is not served before login. `loginUrl()` returns `/outpost.goauthentik.io/start?rd=` + `encodeURIComponent(target)` (current path+search+hash under `/sea-speed/`, else `/sea-speed/`); `openLogin()` stops any previous poll, opens `window.open(loginUrl(), "sea-speed-login", "width=520,height=680")` and polls `/sea-speed/api/session` every 1500 ms (max 200 attempts), and on a truthy `username` stops polling, closes the popup, then `location.reload()` under `/sea-speed/` or `location.href="/sea-speed/"` otherwise; `showOverlay()` is idempotent (existence guard on `#seaSpeedLoginOverlay`) and builds a fixed full-screen overlay (role=dialog, aria-modal) with `#seaSpeedLoginBtn` labelled «Войти» wired via addEventListener; the helper auto-wires `#loginBtn` on DOMContentLoaded. (2) The wiring: `frontend/root/index.html` gains `<button id="loginBtn" type="button">Войти</button>` after the primary link plus `<script src="/login-popup.js"></script>`; the four app pages (`frontend/sea-speed/index.html`, `road/index.html`, `objects/index.html`, `cameras/index.html`) load the helper immediately before their own page script. (3) The retarget: the four page scripts (`frontend/sea-speed/main.js`, `road/main.js`, `objects/registry.js`, `cameras/cameras.js`) change `redirectForReauthentication()` to call `SeaSpeedAuth.showOverlay()` instead of `location.assign(...)`/`window.top.location.replace(...)` — the `sessionRedirecting` guard stays, so session loss shows the overlay instead of navigating. (4) The deploy contour: `deploy/vps/deploy.sh` mirrors every `unavailable.js` touchpoint (`LOGIN_POPUP_TARGET`/`LOGIN_POPUP_URL` vars, `release_complete -f`, required-file loop, install-to-release, bootstrap capture with `.absent`, module-state check, conditional staging `.next`, mv-promote, verify smoke) and both exact-artifact vps lists (`scripts/quality/build_exact_artifacts.py`, `scripts/quality/validate_exact_artifacts.py`) carry the helper. (5) Oracles — new `tests/test_login_popup.py` (`LoginPopupContract`, 9 tests: source pins plus three node behavioural twins with stubbed `window`/`document`/`location`/`fetch` and fake timers); the harness `tests/support/frontend_html.py` gains `WEB_ROOT_SCRIPTS` so the executed twins load the web-root helper and its `document.getElementById` stub becomes DOM-faithful; four oracles retargeted without weakening any assertion (`tests/test_auth_session_frontend_contract.py`, `tests/test_auth_logout_contract.py`, `tests/test_vps_deploy_transaction.py`, `tests/test_665_water_page_assets.py`).

## Decisions
- Popup instead of iframe: `auth.mostdef.ru` sends `X-Frame-Options: DENY`, so iframe embedding is impossible without changing authentik settings — IAM, outside delegated authority; `window.open` needs no edge or IAM change and works from the public landing.
- Edge-free scope: the `/sea-speed/` shell is auth-protected so its HTML is not served before login; the helper therefore deploys to the public web root (`/login-popup.js`, mirroring `unavailable.js`) and the public landing carries the «Войти» button.
- Poll-based completion instead of cross-window messaging: the popup navigates the authentik host while the opener stays on `mostdef.ru`, so postMessage coupling is avoided — the opener polls `/sea-speed/api/session` every 1500 ms (bounded at 200 attempts) and navigates on the first truthy `username`.
- Overlay instead of navigation on session expiry: `redirectForReauthentication()` keeps its `sessionRedirecting` guard and only the navigation call is retargeted to `SeaSpeedAuth.showOverlay()` — the operator keeps the page state and re-authenticates in a popup; a successful login reloads the page.
- addEventListener-only wiring: no inline event handlers anywhere in the helper, so the production CSP is unchanged (the site CSP has no `frame-src` and needs none — no iframe is used).
- Deploy contour mirrors `unavailable.js` exactly: every lifecycle touchpoint (TARGET/URL vars, release_complete, required loop, install-to-release, bootstrap capture with `.absent`, module-state check, staging, promote, smoke) plus both exact-artifact vps lists, so the release archive and the validation gate agree on the new public artifact.
- Harness DOM-faithfulness: `WEB_ROOT_SCRIPTS = {"/login-popup.js": "frontend/sea-speed/login-popup.js"}` maps the web-root absolute src so the executed twins load the real helper, and the `document.getElementById` stub returns null for ids absent from the page HTML — otherwise the overlay's existence guard would pass vacuously.

## Runtime feedback
- Issue #710: on the pre-change tree a session loss inside the app navigated the whole page (`location.assign(...)` / `window.top.location.replace(...)` to the auth start URL), and the public landing offered no login affordance.
- Constraints discovered and documented: `auth.mostdef.ru` sends `X-Frame-Options: DENY` (iframe embedding impossible without changing authentik settings — IAM, outside delegated authority); the site CSP has no `frame-src`; the `/sea-speed/` shell is auth-protected so its HTML is not served before login.
- Harness fidelity fix during implementation: the executed-twin `document.getElementById` stub returned an element for any id, which would have let the overlay's existence guard pass vacuously; it became DOM-faithful (null for ids absent from the page HTML) so the guard behaves like a real browser.
