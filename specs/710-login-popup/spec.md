# Spec: login popup replaces the full-page auth redirect

- Issue: #710

## Product outcome
The login flow gets the popup the owner asked for instead of the full-page redirect (issue #710). Constraints discovered and documented: `auth.mostdef.ru` sends `X-Frame-Options: DENY` (iframe embedding impossible without changing authentik settings — IAM, outside delegated authority); the site CSP has no `frame-src`; the `/sea-speed/` shell is auth-protected so its HTML is not served before login. The chosen scope is therefore edge-free: a new public helper `frontend/sea-speed/login-popup.js` — deployed to the public web root as `/login-popup.js`, mirroring `unavailable.js` — exposes `window.SeaSpeedAuth = {openLogin, showOverlay, loginUrl}`; `loginUrl()` returns `/outpost.goauthentik.io/start?rd=` + the encoded current path (or `/sea-speed/`); `openLogin()` opens `window.open(..., "sea-speed-login", "width=520,height=680")` and polls `/sea-speed/api/session` every 1500 ms (max 200 attempts), and on a truthy `username` it stops polling, closes the popup, then `location.reload()` under `/sea-speed/` or `location.href="/sea-speed/"` otherwise; `showOverlay()` is idempotent and builds `#seaSpeedLoginOverlay` (role=dialog, aria-modal) with `#seaSpeedLoginBtn` labelled «Войти» wired via addEventListener (no inline handlers — the CSP is unchanged), and the helper auto-wires `#loginBtn` on DOMContentLoaded. The public landing (`frontend/root/index.html`) gains the «Войти» button and the helper script tag; the four app pages load the helper immediately before their own page script, and their `redirectForReauthentication()` calls `SeaSpeedAuth.showOverlay()` instead of `location.assign(...)`/`window.top.location.replace(...)` — session loss inside the app no longer navigates the page. `deploy/vps/deploy.sh` mirrors every `unavailable.js` touchpoint for the helper and both exact-artifact vps lists carry it.

## User scenarios
- A visitor on the public landing presses «Войти» (`#loginBtn`): a popup window (520×680, name `sea-speed-login`) opens to the authentik outpost start URL carrying the `rd` return-to parameter; after completing login the original page reloads (or navigates to `/sea-speed/`) and the visitor is inside the service.
- An operator working inside the app loses the session (identity loss after establishment): an in-page overlay («Сессия истекла» + a «Войти» button) appears and no navigation occurs; pressing «Войти» opens the same popup, and a successful login reloads the page back into the service.
- Session-loss events fire twice in a row: still exactly one overlay — the helper's existence guard makes `showOverlay()` idempotent, and the overlay button is wired via addEventListener so no inline handler ever touches the CSP.
- A release is deployed: `/login-popup.js` ships to the public web root at every lifecycle touchpoint (release completeness check, required-file loop, install-to-release, bootstrap capture with `.absent`, module-state check, staging, promote, smoke) and both exact-artifact vps lists carry the helper.

## Requirements
1. Public helper: new `frontend/sea-speed/login-popup.js` (deployed to the public web root as `/login-popup.js`, mirroring how `frontend/sea-speed/unavailable.js` deploys to `/var/www/mostdef.ru/unavailable.js`) — an IIFE exposing `window.SeaSpeedAuth = {openLogin, showOverlay, loginUrl}`; `loginUrl()` returns `/outpost.goauthentik.io/start?rd=` + `encodeURIComponent(target)` where target is the current path+search+hash when `location.pathname` starts with `/sea-speed/`, else `/sea-speed/`.
2. Popup flow: `openLogin()` stops any previous poll, opens `window.open(loginUrl(), "sea-speed-login", "width=520,height=680")` and polls `/sea-speed/api/session` every 1500 ms (max 200 attempts, then polling stops); on a truthy `username` it stops polling, closes the popup, then `location.reload()` under `/sea-speed/` or `location.href="/sea-speed/"` otherwise; fetch failures are swallowed.
3. Session-expiry overlay: `showOverlay()` is idempotent (existence guard on `#seaSpeedLoginOverlay`) and builds a fixed full-screen overlay (`role="dialog"`, `aria-modal="true"`) with `#seaSpeedLoginBtn` labelled «Войти» wired via `addEventListener` — no inline event handlers, so the production CSP is unchanged.
4. Landing wiring: `frontend/root/index.html` gains `<button id="loginBtn" type="button">Войти</button>` after the primary link and `<script src="/login-popup.js"></script>`; the helper auto-wires an existing `#loginBtn` on `DOMContentLoaded`.
5. In-app retarget: the four app pages (`frontend/sea-speed/index.html`, `frontend/sea-speed/road/index.html`, `frontend/sea-speed/objects/index.html`, `frontend/sea-speed/cameras/index.html`) load `/login-popup.js` immediately before their own page script, and the four page scripts (`frontend/sea-speed/main.js`, `frontend/sea-speed/road/main.js`, `frontend/sea-speed/objects/registry.js`, `frontend/sea-speed/cameras/cameras.js`) change `redirectForReauthentication()` to call `SeaSpeedAuth.showOverlay()` instead of `location.assign(...)`/`window.top.location.replace(...)` — the `sessionRedirecting` guard stays.
6. Deploy contour: `deploy/vps/deploy.sh` mirrors every `unavailable.js` touchpoint for the helper (`LOGIN_POPUP_TARGET`/`LOGIN_POPUP_URL` vars, `release_complete -f` check, required-file loop, install-to-release, bootstrap capture with `.absent`, `install_release` module-state check, conditional staging `.next`, mv-promote, verify smoke), and both exact-artifact vps lists (`scripts/quality/build_exact_artifacts.py`, `scripts/quality/validate_exact_artifacts.py`) carry `frontend/sea-speed/login-popup.js`.
7. Test contour: new `tests/test_login_popup.py` (`LoginPopupContract`, 9 tests — source pins plus three node behavioural twins with stubbed `window`/`document`/`location`/`fetch` and fake timers, so the runs are deterministic: no network, no sleeps); the harness `tests/support/frontend_html.py` gains `WEB_ROOT_SCRIPTS = {"/login-popup.js": "frontend/sea-speed/login-popup.js"}` so the executed twins load the web-root helper, and its `document.getElementById` stub becomes DOM-faithful (returns null for ids absent from the page HTML) so the overlay's existence guard behaves like a real browser; four oracles retargeted without weakening any assertion: `tests/test_auth_session_frontend_contract.py` (overlay contract + dedicated road scenario), `tests/test_auth_logout_contract.py` (overlay contract), `tests/test_vps_deploy_transaction.py` (new file in the synthetic release + promotion/smoke/rollback/bootstrap enumerations), `tests/test_665_water_page_assets.py` (the web-root absolute `/login-popup.js` allowed and added to the expected script order).

RED authenticity — before implementation the helper did not exist and the landing had no `#loginBtn`, so all 9 tests of `tests/test_login_popup.py::LoginPopupContract` failed (phase RED: 9 failed / 0 passed).
- AC-002: after a successful login the page reloads (or navigates to `/sea-speed/`) and the user is inside the service — the `/sea-speed/api/session` poll resolving a truthy `username` triggers `location.reload()` under `/sea-speed/` or `location.href="/sea-speed/"` otherwise.
- AC-003: on session loss inside the app, an overlay with a «Войти» button appears and no navigation occurs — all four `redirectForReauthentication()` bodies call `SeaSpeedAuth.showOverlay()` and none calls `location.assign(`/`location.replace(`.
- AC-004: the overlay is idempotent (a second `showOverlay()` call does not create a second overlay) and the helper uses no inline event handlers, so the CSP is unchanged.
- AC-005: the deploy contour ships `/login-popup.js` to the public web root at every lifecycle touchpoint, and the full battery plus validators stay green with no assertion weakened.

## Runtime feedback
- Issue #710: on the pre-change tree a session loss inside the app navigated the whole page (`location.assign(...)` / `window.top.location.replace(...)` to the auth start URL), and the public landing offered no login affordance — the owner asked for a login popup instead of the full-page redirect.
- Constraints discovered and documented: `auth.mostdef.ru` sends `X-Frame-Options: DENY` (iframe embedding impossible without changing authentik settings — IAM, outside delegated authority); the site CSP has no `frame-src`; the `/sea-speed/` shell is auth-protected so its HTML is not served before login — these constraints forced the edge-free scope (public helper + landing button + in-app overlay).
- Harness fidelity fix during implementation: the executed-twin `document.getElementById` stub previously returned an element for any id, which would have let the overlay's existence guard pass vacuously; it became DOM-faithful (null for ids absent from the page HTML) so the guard behaves like a real browser.
