# Spec: private-repo deploy chain (protected main without public visibility)

- Issue: #668

## Product outcome
The repository went private (owner action 2026-11-13) and the autonomous deploy chain fails closed on a private repository: `scripts/release/verify_source_protection.py` hard-gates on `visibility=public`, the post-checkout `git fetch` steps cannot authenticate because their checkouts set `persist-credentials: false`, and the VPS release download curls a public GitHub archive URL that no longer exists for a private repo. The outcome: the autonomous deploy chain works for the PRIVATE repository, still fail-closed — the trust boundary is `main` branch protection with the required status checks (`Repository validation`, `quality-integration`), never public visibility. The shipped release archive becomes a runner-built `git archive` of the exact verified DEPLOY_SHA, pre-placed on the VPS via the existing restricted SSH identity, with the curl fallback kept intact (fail-closed when no archive is pre-placed and the download fails). The Ubuntu Worker contour keeps its current behavior and is deferred to a follow-up issue.

## User scenarios
- A merge to `main` of the private repository passes the Quality integration gate; the autonomous router's freshness `git fetch` authenticates with the persisted job credentials, source protection admits the private repository because `main` is protected with the required checks, and the standing-delegation policy evaluates exactly as before.
- An allowed VPS deploy builds the exact source archive on the runner from the verified DEPLOY_SHA, copies it to `/opt/sea-speed-deploy/state/<SHA>.tar.gz` over the pinned SSH transport, and `deploy/vps/deploy.sh` consumes the pre-placed archive (no curl, no tokens) while keeping the existing completeness checks, sha256 recording and `--strip-components=1` extraction for both the pre-placed and the curl path.

## Requirements
1. `scripts/release/verify_source_state` admits a PRIVATE repository when `main` reports `protected=true` with the required contexts, and still fails closed when protection is not active ("protection is not active") or required checks are missing ("missing required status checks"); the success line prints the ACTUAL visibility derived from the repository payload (visibility field, fallback derived from the private flag).
2. `.github/workflows/deploy-runtime-autonomous.yml` and `.github/workflows/deploy-vps.yml` checkouts keep credential persistence enabled (no `persist-credentials: false`) so the post-checkout `git fetch` steps authenticate; `.github/workflows/deploy-ubuntu-worker.yml`'s checkout is NOT changed (Ubuntu contour deferred).
3. `.github/workflows/deploy-vps.yml` gains a step before the deploy step that creates `dist/exact/sea-speed-src-${DEPLOY_SHA}.tar.gz` via `git archive --format=tar.gz --prefix="sea-speed-${DEPLOY_SHA}/"` of the exact verified DEPLOY_SHA, pre-creates `/opt/sea-speed-deploy/state` idempotently over SSH, and scp's the archive to `/opt/sea-speed-deploy/state/${DEPLOY_SHA}.tar.gz` with the same identity/options as the deploy step, gated on the same non-empty VPS_HOST/VPS_USER checks; no tokens or secret values appear in argv or logs.
4. `deploy/vps/deploy.sh` `download_release` uses a pre-placed archive when present — `SEA_SPEED_RELEASE_ARCHIVE` override, default `$DEPLOY_ROOT/state/${COMMIT_SHA}.tar.gz` (the scp target) — logging "Using pre-placed release archive" and copying it into place; otherwise the existing curl runs unchanged. sha256 recording, completeness validation and `tar --strip-components=1` extraction apply to BOTH paths; curl remains the fail-closed fallback.
5. The flow marker "Verify public protected production source" is renamed to "Verify protected production source" atomically across the three deploy workflows (step name, comment markers, summary lines), `.github/actions/verify-exact-release/action.yml` (step name, description) and `scripts/quality/validate_workflow_policy.py` (markers + success text); no "Verify public protected production source" or "protected public main" remains outside tests/ and historical specs/.
6. Governing docs (contracts/SEA_SPEED_DELIVERY_POLICY.md, contracts/runtime/RELEASE_READINESS_GATE.md, contracts/branches/deploy.md, specs/README.md, docs/WORKFLOW_OVERVIEW.md, docs/operations/UBUNTU_ZERO_TOUCH_DEPLOYMENT.md) stop mandating public visibility: production source may be private; protection = branch protection + required status checks. Minimum diff, structure intact.

- AC-002: tests.test_autonomous_execution_policy (11 tests) proves the workflow contract — both deploy checkouts keep persisted credentials for the post-checkout `git fetch`, the flow marker reads "Verify protected production source" in all three workflows (parsed step-name twin included), and the router/composite policy chain is unchanged.
- AC-003: tests.test_vps_deploy_transaction (24 tests) proves the VPS transaction — the pre-placed release archive path skips curl entirely (sentinel fake), still computes and records the archive sha256, and deploys successfully; every pre-existing rollback/boundary/degraded transaction behavior is unchanged.
- AC-004: `python3 scripts/quality/validate_workflow_policy.py`, `validate_quality_contracts.py`, `scripts/ci/validate_sdd.py` and the full unittest battery are green; `git diff --stat` shows only the allowed paths.
