# Spec: wave-7 worker live — live-publisher family extraction (move-only)

- Issue: #397
- Specification: specs/397-wave7-worker-live/spec.md

## Product outcome

Waves 1-6 extracted the pure kernel, the media/reader layer, the cv2 render/snapshot layer, the requests transport/posting layer (waves 4-5) and the crossing analytics domain (wave 6); the worker still mixes the live-publisher family with the ROI cluster, the speed-lines domain and the supervision main loop. Wave 7 extracts the live-publisher family verbatim (move-only, byte-identical bodies) into NEW `worker/worker_live.py`: the 3 publish-thread state literals (`_LIVE_PUBLISH_QUEUE`, `_LIVE_PUBLISH_LOCK`, `_LIVE_PUBLISH_THREAD`) and the 3 publisher defs (`_live_publisher_loop`, `_ensure_live_publisher`, `post_live_envelope`) — two regions (state literals 127-129; defs 466-502 at main 20657e7) cut bottom-up with the standing blank-pair discipline.

The wave's central mechanism is the thread-lifecycle ownership: queue/threading are allowed in worker_live BY DESIGN — this module OWNS the publish-thread lifecycle (the bounded queue, its lock and the daemon thread are created, started and drained here and nowhere else). The loop's network body (`_post_live_envelope_sync`) already moved to worker_transport in wave 5; worker_live imports it (import chain live → transport → kernel stays acyclic). Object-identity coupling: `_LIVE_PUBLISH_QUEUE` and `_LIVE_PUBLISH_LOCK` are defined ONCE in worker_live and re-exported BY IDENTITY — nothing in the whole worker source set rebinds them (every access is a method call on the same Queue/Lock objects), so the publisher loop and the staying worker callers share ONE queue and ONE lock. `_LIVE_PUBLISH_THREAD` is the single rebinding name: it moves WITH its sole rebinder `_ensure_live_publisher` (the only `ast.Global` naming it sits in that def) — the pair is never split. Unlike wave 6, the state names ARE re-exported: the re-export preserves object identity for the queue/lock/thread at import time and the ns-injection/monkeypatch surface; for the one rebinding name `_LIVE_PUBLISH_THREAD` the rebinds are scoped to worker_live's namespace (the worker-ns re-export copy is a frozen import-time snapshot) and no worker-namespace reader exists — enforced by the no-Load guard in the module test; the 3 def names ARE re-exported via a third flat sibling ImportFrom (allowed: the transport/crossings pins filter on their own `node.module` values), keeping the staying `post_live_envelope(env_live)` call sites in the supervision main loop and global-name resolution intact.

Deliberate STAYS in the worker (recorded, not silently dropped, with forced reasons):
- `_roi_processing_points`, `prepare_roi_processing_frame`, `detection_inside_road_roi`, `roi_processing_signature`, `draw_roi_polygon`, `parse_road_roi_polygon`, `road_roi_enabled` — the ROI family: `_roi_processing_points` REBINDS via `global` + assignment and the family's callees are cv2/numpy (off the live import allowlist by construction).
- `_line_speed_state` + `update_speed_lines_estimate` — the speed-lines analytics domain: the state's sole consumer stays.
- `detect_vehicles`, `build_road_live_envelope`/`build_water_live_envelope`, `main` and the track/event pipeline — the supervision main loop and its callees (cv2/numpy/ultralytics domain) are outside the live cut.

Convergence is fail-closed everywhere the new deployable ships: the compatibility gate's `MODULE_SOURCES` extends 5→6 (six-file union, semantics unchanged), `validate_repo` REQUIRED_FILES, `build_exact_artifacts` (ubuntu-worker AND edge), `validate_exact_artifacts` (ubuntu-worker AND edge) and the installer's prepared-release required loop all gain `worker/worker_live.py`, so a payload missing the flat sibling fails at CI or install — never silently at boot. Two dead imports (`import queue`, `import threading` in the worker) are removed as a forced consequence of the cut: the sole uses (state literals 127-129 + defs 466-502 pre-cut) all moved; ruff F401 would fail CI otherwise.
