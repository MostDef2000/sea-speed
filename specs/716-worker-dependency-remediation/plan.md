# Plan: Ubuntu worker dependency remediation — clear the four advisory-bearing transitive pins in the runtime lockfile

- Spec: specs/716-worker-dependency-remediation/spec.md

## Architecture
`deploy/worker/ubuntu/requirements-runtime.lock.txt` is the resolved, hash-pinned graph the Ubuntu worker installs, and `deploy/worker/ubuntu/runtime-lock.json` is its schema-2 companion. `prepare-runtime.sh` validates the pair before any mutation: the lockfile must start with `# sea-speed-runtime-lock-v1`, be non-empty, and carry a sha256 hash on every requirement line; `runtime-lock.json resolved_lock.sha256` must equal the SHA-256 of the lockfile bytes; each `pytorch.artifact_sha256` digest must appear in the lockfile's hash lines for that package. The runtime then installs in two phases — `pip download --require-hashes --only-binary=:all:` into a wheelhouse, then `pip install --no-index --find-links` from the verified set — into `runtimes/<runtime-id>`, where the id is `sha256(runtime-lock.json bytes + NUL + requirements-runtime.txt bytes + NUL + lockfile bytes)`. The deploy transaction (`update-exact.sh` via `install-manual.sh`) prepares the release and runtime, activates the units, and `deploy-authorized.sh` verifies the active target.

This change rewrites the lockfile with exactly four pins moved and updates the digest field, so the pair stays a matching pair and the runtime id necessarily moves — which is the intended new-runtime signal for the deploy transaction. Regeneration used `uv pip compile --generate-hashes --index-url https://download.pytorch.org/whl/cu130 --extra-index-url https://pypi.org/simple --index-strategy unsafe-best-match --python-version 3.14` with a temporary `-c runtime-constraints.txt` pinning the 53 non-target packages to their current versions plus `--upgrade-package` for the four targets; the generated `# via` comments that named the temporary constraints file were stripped and the header restored to the canonical `uv pip compile ... runtime-lock-input.txt -o requirements-runtime.lock.txt` form the resolver workflow emits, so the committed file is self-contained. `runtime-lock.json` changes only in `resolved_lock.sha256` (`e20d765263221f52ac4b7cb55a522d627eec122b300514e5012b37b300aebbca`). No executable code consumes the version numbers directly: the deploy path consumes the digest pair, and `verification_imports` proves the runtime still imports cv2, lap, numpy, requests, torch, torchvision and ultralytics.

## Decisions
- Pin the 53 non-target packages and upgrade only the four targets instead of re-resolving the whole graph: a full resolution would pull unrelated transitive changes into a security patch, widening both the diff and the regression surface for no need.
- Regenerate hashes with uv rather than editing version numbers by hand: `--require-hashes` installs demand every wheel's real digest, and hand-edited digests would fail closed at download time or, worse, never be exercised locally.
- Strip the temporary constraints references from the generated `# via` comments and restore the canonical header: the committed lockfile must not reference `runtime-constraints.txt`, a file that does not exist in the repository, and it must keep exactly the shape the resolver workflow produces so a future regeneration is a clean diff.
- Update the lockfile and `runtime-lock.json` in the same commit: the digest is defined over the exact lockfile bytes, so the two must never be reviewed or merged separately.
- Bump all four packages, not only the largest advisory group: leaving filelock, certifi or setuptools at their advisory versions keeps the audit red and reopens the same finding for the same graph.
- Keep `torch`/`torchvision` and the PyTorch provenance block untouched: their artifact digests are a separate hardware-bound provenance contract, and none of the 58 advisories names them.
- Accept the pillow major bump with the available evidence instead of pinning pillow 12.x: the advisory fix version is 13.0.0, so a 12.x pin cannot clear the audit; the full battery, the exact-head CI re-run and the deploy transaction's post-activation checks are the regression gates, and the residual is recorded in RISK-001.
- Change Contract declaration is load-bearing: `deploy/worker/ubuntu/**` is in the diff, so the autonomous policy derives `Production impact: UBUNTU_WORKER` and `Ubuntu worker/relay update: REQUIRED`. The PR must declare `Production impact: UBUNTU_WORKER`, `VPS deployment: NOT REQUIRED`, `Ubuntu worker/relay update: REQUIRED`, `Production safety envelope: REQUIRED`, `VPS execution capability: NOT APPLICABLE`, `Ubuntu worker execution capability: CONNECTOR`, `Operator actions expected: 0`; an undeclared or contradicting contract is rejected before merge.

## Runtime feedback
- The defect was a coverage gap, not a bad credential or a flaky gate: the audit read the 7 direct pins and the runtime installed the 57-pin resolved graph, so four advisory-bearing packages were structurally invisible. The fix is data-only because the gate already existed; the missing input was the lockfile.
- Evidence chain: the #686 full-lockfile audit in Security gates run `44975403396` produced `pip-audit-reports-4aa072f20ca90928b74aea0a83a81b7075d2add8.zip` with 58 advisories (pillow 42, filelock 13, certifi 2, setuptools 1) against the worker lockfile while the direct-manifest job was green.
- Implementation feedback: the constraints-file technique is what keeps the change a security patch rather than a dependency refresh — it pinned 53 packages so only the four targets could move, and the four resulting versions are all at or above their fix versions. Stripping the temporary constraints path from `# via` comments and restoring the header is required for self-containment; without it the committed file would reference a non-existent file and look unlike a resolver artifact.
- Verification feedback: the local OSV run corroborates 0 advisories for both contours, but the authoritative re-check is the CI audit with the default advisory service, because the sandbox cannot reach that service and the original finding came from it.
- Risk feedback: pillow 12 to 13 is the one major bump; the unit battery proves imports and lock integrity, not pixel-level behaviour, so the deploy transaction's post-activation identity checks plus exact-head CI are the production gate, and the residual is stated rather than hidden.
