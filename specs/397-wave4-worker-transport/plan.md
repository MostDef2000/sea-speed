## Architecture

- worker_transport.py: the requests transport/posting layer over the kernel — imports worker_kernel (env readers, API URL builders, ROI geometry scaling) and worker_media (_resolve_frame_size) plus requests/json/time/pathlib; NO cv2/numpy (render/detection layers), NO ultralytics/av (model/media), NO subprocess/socket (pinned by test).
- hls_motion_yolo_worker_events.py: keeps analytics/crossing/speed domain state (the staying mutables `_crossing_counts`/`_crossings_by_class`/`_crossing_track_sides`/`_crossing_pending_posts`/`_crossing_vlz_date`/`_line_speed_state`/`_roi_processing_points`/`_speed_track`/`_track_states`/`_speed_config_cache`), the live-publisher loop, water_passage engine calls, MotionDetector/detect_vehicles and main(). Staying callers of moved helpers (road_roi_enabled/parse_road_roi_polygon/prepare_roi_processing_frame → fetch_remote_roi; update_crossing_counts → fetch_crossing_line_config; update_speed_lines_estimate/draw_speed_lines_overlay/main → fetch_speed_lines_config; main → post_state/post_event/post_passage) resolve via worker-module globals where the re-export lives (C-4: internal calls resolve PER-MODULE — e.g. fetch_speed_lines_config's internal `_speed_lines_cache` reads bind to WORKER_TRANSPORT's globals, which is why that cache was imported INTO worker_transport and re-exported back).
- Import cycle safety: worker_transport imports worker_kernel + worker_media, never the worker → no cycle (chain transport→media→kernel); the worker's `from worker_transport import ...` sits after the render re-export, sibling style.
- Cache identity model (the wave-4 extension of the re-export contract): the three TTL caches are module-level MUTABLES mutated only in place; the re-export exposes the SAME objects in both namespaces; the AST guard forbids any future rebinding (the one rebinding global, `_roi_processing_points`, is deliberately worker-resident and untouched by movers).
- Gate scan model: REQUIRED_ENV_NAMES union across the FOUR MODULE_SOURCES files — after the move the union is exactly the pre-wave-4 set (HLS_URL in worker_media; SEA_SPEED_API_URL/TOKEN now in worker_transport; MODEL_NAME in the worker); the post_* env reads moving INTO the union is precisely why the gate stays green.

## Decisions

- D-1: Verbatim byte-level move (script-extracted regions, bottom-up) instead of retyping: guarantees AST-identity, verified programmatically after the move against `git show HEAD` (9/9 names identical, 64 staying defs intact, zero duplicate defs).
- D-2: The three TTL caches MOVE with their fetchers under an OBJECT-IDENTITY contract (re-exported as objects, not copied): the safety argument is (a) zero rebindings verified by AST audit, (b) all other accesses are in-place mutations visible through both names, (c) the identity pin test enforces the contract going forward. This is the first wave moving module-level STATE; the argument is documented here per the work order.
- D-3: `_crossing_line_cache` moves despite a staying reader (crossing_overlay_summary): the reader uses only `.get()` (read-only), the mover only item-assigns/.updates — with object identity the staying reader observes mover mutations exactly as before the split (the work order's explicit allowance, verified against the live use map).
- D-4: `_speed_config_cache` + `fetch_speed_config` STAY: the fetcher is not in the work-order cut; the cache never moves without its fetcher. `_crossing_counts`/`_crossings_by_class` STAY: crossing-domain state whose mutators (update_crossing_counts/reset_crossing_counts) and reader (crossing_overlay_summary) all stay — moving them would strand staying mutators from their state (bare-name writes in the worker would hit the re-export binding, which works for in-place mutation, but the cluster has no mover to justify the move).
- D-5: Transport allowlist = requests/json/pathlib/time + repo-pure worker_kernel/worker_media; the worker_media join is the DOCUMENTED deviation from the order's baseline list (the order anticipated kernel-only helpers; the sweep found `_resolve_frame_size` needed by all three fetchers — it moved to worker_media in wave 2). cv2/numpy/ultralytics/av/subprocess/socket are explicitly forbidden at module level by a dedicated test.
- D-6: NO monkeypatch-target transfers were needed this wave (C-4 analysis recorded): tests that inject fakes do so via exec-namespace injection (test_line_crossing/test_worker_contract/test_worker_roi_pipeline) — the injected fake replaces the re-export binding in the worker's namespace, so staying callers still see it; attribute-based patches (`_ORIGINAL_POST_STATE = worker.post_state` in ubuntu_worker_entrypoint, `entry.post_state` calls in test_detection_runtime_optimization) resolve through the re-export to the same function object. Zero test edits beyond the recorded contract transfers.
- D-7: Contract transfers (work-order-sanctioned, not pin fixes): test_worker_kernel_module STAYING_NAMES loses fetch_remote_roi (down to 3 names); test_worker_media_module STAYING_IN_WORKER loses fetch_remote_roi (down to 4); test_worker_render_module STAYING_IN_WORKER loses fetch_remote_roi/post_state/post_event/post_passage (down to 5) — each transfer recorded here per the work order.
- D-8: validate_sdd GRANDFATHERED_PREFIX_COLLISIONS "397" gains the wave-4 dir — the scheduled exact-set break continuing the waves-2/3 pattern; mirrors the 396 staged-wave precedent.
