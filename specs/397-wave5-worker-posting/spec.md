# Spec: wave-5 worker posting — crossing/speed-config posting surface extraction (move-only)

- Issue: #397
- Specification: specs/397-wave5-worker-posting/spec.md

## Product outcome

Wave 4 extracted the requests transport/posting layer into `worker/worker_transport.py` and left the crossing/speed-config posting surface in the worker as recorded STAYS. Wave 5 completes the transport extraction VERBATIM (move-only, byte-identical bodies): 4 defs (`fetch_speed_config`, `post_crossing`, `flush_crossing_posts`, `_post_live_envelope_sync`) plus the 2 module-level state objects that move WITH their owners (`_speed_config_cache` with its sole consumer `fetch_speed_config`; `_crossing_pending_posts` with its mover `flush_crossing_posts`) move into worker_transport.py, keeping the wave-4 OBJECT-IDENTITY re-export contract for module-level state.

The `_crossing_pending_posts` decision is the wave's central mechanism and mirrors the wave-4 cache contract: the ONLY Store access to the name in the whole worker+transport source is its defining list literal (moved into worker_transport); every other access is an in-place mutation — the staying mutators `update_crossing_counts` (`.append`) and `reset_crossing_counts` (`.clear`) act through the worker's re-exported SAME list object, and the mover `flush_crossing_posts` (`.pop(0)` / `[0]` reads / truthiness) mutates the same object from worker_transport. Because Python's ImportFrom re-export preserves object identity, `worker._crossing_pending_posts` IS `worker_transport._crossing_pending_posts` — mover and staying mutations stay coherent exactly as before the split. `_speed_config_cache` has the same shape: its only reader/writer is the moved `fetch_speed_config` (item assignment only; zero rebindings), and the staying caller `convert_px_s_to_kmh` resolves `fetch_speed_config` through the re-export.

Deliberate STAYS (recorded, not silently dropped, with forced reasons):
- `update_crossing_counts`, `reset_crossing_counts`, `prune_crossing_tracks`, `maybe_reset_daily_crossings`, `vlz_date`, `crossing_overlay_summary` + their domain state `_crossing_counts`, `_crossings_by_class`, `_crossing_track_sides`, `VLZ_TIMEZONE`, `_crossing_vlz_date` — crossing-domain logic: `datetime`/`timezone` are not in TRANSPORT_IMPORT_ALLOWLIST (the allowlist is frozen by test and gains nothing this wave); `_crossing_vlz_date` REBINDS via a `global` statement (worker:608→612 pre-move) which violates the AST no-rebinding guard that protects moved state names; `crossing_overlay_summary` is additionally pinned by the wave-3 render STAYS and the `globals()`-guard call site in `build_road_live_envelope`.
- `_LIVE_PUBLISH_QUEUE`, `_LIVE_PUBLISH_LOCK`, `_LIVE_PUBLISH_THREAD` + `_live_publisher_loop`, `_ensure_live_publisher`, `post_live_envelope` — the live-publisher loop: `threading`/`queue` are off the transport import allowlist and `_LIVE_PUBLISH_THREAD` REBINDS (`_ensure_live_publisher`), so the loop stays in the worker; `_post_live_envelope_sync` (the loop's network body) moves and the staying caller resolves it via the re-export.
- `_roi_processing_points`, `prepare_roi_processing_frame`, `detection_inside_road_roi`, `road_roi_enabled` — ROI cluster: `_roi_processing_points` is a rebinding global (worker `global` + assignment in staying `prepare_roi_processing_frame`) with cv2/numpy callees — off-allowlist for transport.
- `_line_speed_state` — sole consumer `update_speed_lines_estimate` stays (analytics domain, staying mutators).

No convergence-list edits are required: worker_transport.py is already in validate_repo REQUIRED_FILES, build_exact_artifacts (ubuntu-worker AND edge), validate_exact_artifacts, and the install-systemd.sh prepared-release loop (all from wave 4). The compatibility gate stays the four-file union — the moved env reads (SEA_SPEED_API_URL/SEA_SPEED_API_TOKEN in post_crossing/_post_live_envelope_sync) land in a module the gate already scans. One dead import (`import requests` in the worker) is removed as a forced consequence of the cut: after the move the worker no longer references `requests` (ruff F401), and the gate's union scan does not pin requests in the worker file.
