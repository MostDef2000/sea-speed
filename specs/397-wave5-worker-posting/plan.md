## Architecture

- worker_transport.py: the requests transport/posting layer over the kernel — wave 5 adds the crossing/speed-config posting surface to the SAME module: `post_crossing`/`flush_crossing_posts` + `_crossing_pending_posts` join the posting section (after `post_passage`), `_post_live_envelope_sync` joins them (the network body of the staying live-publisher loop), and `_speed_config_cache`/`fetch_speed_config` join the fetcher section (after `fetch_crossing_line_config`). Imports stay: requests/json/time/pathlib + worker_kernel (now ×9) + worker_media (×1). NO cv2/numpy, NO ultralytics/av, NO subprocess/socket, NO datetime/threading/queue.
- hls_motion_yolo_worker_events.py: keeps analytics/crossing/speed domain state and the live-publisher loop. Staying callers of moved helpers resolve via the single flat re-export: `convert_px_s_to_kmh` → `fetch_speed_config`; `main` → `flush_crossing_posts`; `_live_publisher_loop` → `_post_live_envelope_sync`. The staying crossing mutators keep BARE-NAME access to `_crossing_pending_posts` (`update_crossing_counts` appends, `reset_crossing_counts` clears) — the name binds to the re-exported SAME list object, so mover (transport) and staying (worker) mutations stay coherent.
- Import cycle safety: unchanged from wave 4 — worker_transport imports worker_kernel + worker_media, never the worker (chain transport→media→kernel acyclic); the worker's single re-export block sits after the render block, before first use.
- State identity model (wave-5 extension of the wave-4 cache contract): the two moved state objects are module-level MUTABLES mutated only in place; the re-export exposes the SAME objects in both namespaces; the AST no-rebinding guard (worker+transport) now covers 5 names and forbids any future rebinding. The recorded STAYS include every rebind-heavy cluster (`_crossing_vlz_date`, `_LIVE_PUBLISH_THREAD`, `_roi_processing_points`) precisely because a rebinding name cannot move under this contract.
- Gate scan model: unchanged — REQUIRED_ENV_NAMES union across the FOUR MODULE_SOURCES files; the wave-5 moved env reads (SEA_SPEED_API_URL/SEA_SPEED_API_TOKEN in post_crossing/_post_live_envelope_sync) land in worker_transport, which the gate already scans.

## Decisions

- D-1: Verbatim byte-level move (script-extracted regions, bottom-up) instead of retyping: guarantees byte- and AST-identity, verified programmatically after the move against `git show d92e811` (5/5 regions byte-identical, 6/6 names AST-identical, moved names gone from worker, zero duplicate defs).
- D-2: `_crossing_pending_posts` moves WITH `flush_crossing_posts` under the OBJECT-IDENTITY contract (must-move-together: flush calls post_crossing by bare name, and transport cannot import the worker without a cycle): the safety argument is (a) zero rebindings verified by AST audit (the only Store access is the defining literal, moved into worker_transport), (b) all other accesses are in-place mutations visible through both names, (c) the identity pin test and the AST no-rebinding guard enforce the contract going forward.
- D-3: `_speed_config_cache` moves with its sole accessor `fetch_speed_config` (wave-4's recorded STAY is superseded by this wave's cut; the wave-4 reason — "the cache never moves without its fetcher" — is honored: fetcher and cache move together).
- D-4: The recorded STAYS are forced, not stylistic: crossing-domain mutators/state stay because `datetime`/`timezone` are off the frozen transport allowlist and `_crossing_vlz_date` REBINDS via `global` (would fail the no-rebinding guard); the live-publisher loop stays because `threading`/`queue` are off-allowlist and `_LIVE_PUBLISH_THREAD` rebinds; the ROI cluster stays because `_roi_processing_points` rebinds and its callees are cv2/numpy; `_line_speed_state` stays with its sole consumer `update_speed_lines_estimate`; `crossing_overlay_summary` stays (render STAYS pin + `globals()`-guard call site in `build_road_live_envelope`).
- D-5: One dead `import requests` is removed from the worker as part of the cut (forced deviation recorded in the progress file): after the move the worker no longer references `requests` (AST-verified: zero Name nodes), ruff F401 would fail CI, and the compatibility gate's union scan does not pin requests in the worker file. The worker's kernel ImportFrom keeps `get_speed_config_url` as part of the wave-1 re-export surface (noqa F401 block, untouched per the work order).
- D-6: NO monkeypatch-target transfers and NO #398 pin edits this wave: the ns-injection fakes (test_line_crossing extract_worker_functions / RetryQueueTests) are exec-based and location-independent — the harness resolves moved defs from worker_transport (first-definition-wins across the five sources) and injected fakes replace bare names in the exec namespace; attribute reads through the worker re-export (e.g. hls_motion_yolo_runtime.py `worker.fetch_speed_config`) resolve to the same function objects. Zero test edits beyond the wave-5 tuple extension.
- D-7: validate_sdd GRANDFATHERED_PREFIX_COLLISIONS "397" gains the wave-5 dir — the scheduled exact-set break continuing the 396/waves-1-4 pattern.
