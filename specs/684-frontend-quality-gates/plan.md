# Plan: frontend quality gates — an ESLint no-undef gate and a real six-page browser smoke

- Spec: specs/684-frontend-quality-gates/spec.md

## Architecture
Two independent gates in the existing `static-contract-security` job of `.github/workflows/quality-integration.yml`, no new job, no trigger or permission change. (1) Static gate — `eslint.config.mjs` (flat config), `eslint` 10.15.0 + `globals` 17.14.0 exact-pinned in `package.json` with a committed `package-lock.json`; the config targets `frontend/**/*.js` with `sourceType: "script"`, `no-undef: error` and the `globals.browser` set plus five cross-script globals (`SeaSpeedOverlayCanvas`, `SeaSpeedAuth`, `SeaSpeedLiveSync`, `Hls`, `registryScopeKey`); `npm run lint:js` is `eslint frontend` and is non-mutating (no `--fix`). (2) Browser smoke — `@playwright/test` 1.65.1 exact-pinned, `playwright.config.mjs` Chromium-only with `testDir: ./tests/browser`, `retries: 0`, 20 s per-test timeout, 120 s global timeout, `baseURL http://127.0.0.1:8131` and no `webServer`; `tests/browser/fixture-server.mjs` serves the six real operator pages and every script URL those pages reference with the production enforcing CSP as a real response header and deterministic API/session fixtures, intercepting only the CDN `hls.js` tag via `page.route` and fulfilling it with a local stub (that one tag's SRI/`crossorigin` attributes are stripped because a synthetic stub cannot match the pinned digest — documented and asserted); `tests/browser/operator-pages.spec.mjs` holds 8 tests — one per operator page (exact CSP header, every script `src` 200, page-specific readiness, zero uncaught exceptions, zero CSP violations) plus an hls-stub proof and a CSP-enforcement proof; `npm run test:browser` is `playwright test`. (3) CI wiring — four steps inserted immediately after the SHA-pinned `Set up Node.js` step: `npm ci --ignore-scripts`, `npm run lint:js`, `npx playwright install --with-deps chromium`, `npm run test:browser`; everything else in the workflow is untouched, and no other workflow gains a step.

## Decisions
- ESLint `no-undef` as the binding-correctness gate: the two shipped bugs (`d` in road `loadSpeedConfig`, `line` in the `cxOffBtn` re-enable handler) are exactly the class `node --check` cannot see — it validates syntax, not identifier resolution — so a lint pass with `no-undef: error` is the smallest oracle that catches them without touching frontend source.
- Five explicit cross-script globals instead of `/* global */` comments or per-file overrides: the frontend is script-typed and shares five values across files, so listing them once in the flat config keeps the gate honest for every file. `registryScopeKey` is the load-bearing discovery — a top-level `let` in `objects/registry.js` read by `objects/crossings.js`; omitting it would produce a false positive on the objects page and invite a suppression habit.
- Real headless Chromium instead of a heavier CSP-only parser: the audit showed the CSP oracle never saw the objects page, so the gap was page coverage, not policy parsing; a browser smoke that loads the real pages against the real CSP header closes both the coverage and the execution-truth gap in one bounded suite.
- Fixture server owns the CSP header: the production enforcing policy is served as a real response header by `tests/browser/fixture-server.mjs`, so a CSP violation surfaces as a browser event in the same run; the evidence limit (browser enforcement of the supplied policy, NOT deployed nginx inheritance) is stated in `tests/browser/README.md` rather than implied.
- Local hls.js stub with an asserted attribute strip: a synthetic stub cannot reproduce the pinned CDN digest, so `page.route` fulfils that one request and the fixture removes only that tag's SRI/`crossorigin` attributes; the strip is visible in the fixture and asserted by the stub-proof test, so it cannot silently widen.
- Retries 0 with bounded timeouts: a flaky browser test that auto-retries hides real regressions; 20 s per test and 120 s global keep the whole suite inside the existing 15-minute job budget while a red result stays a real defect.
- `npm ci --ignore-scripts` from a committed lockfile and no new `uses:` actions: reproducibility and supply-chain surface stay bounded — no lifecycle scripts execute, no third-party action is added, and the workflow keeps `permissions: contents: read`.
- No change to `package.json` in this delivery step: the deterministic tooling manifest, lockfile and configs were authored by the preceding implementation worker with the exact pins above; this step only wires CI and records the SDD trio, so the gate inputs are fixed by pin, not by this edit.

## Runtime feedback
- The audit found two `no-undef` defects (`d` in road `loadSpeedConfig`, `line` in the `cxOffBtn` re-enable handler) that shipped through a fully green CI: neither `node --check` nor the CSP oracle can observe identifier resolution, so the green result was evidence of syntax and policy, not of binding correctness.
- The CSP oracle also never exercised the objects page, so one of the six operator pages had no automated page-level signal at all.
- Implementation feedback: the static gate needed `globals.browser` plus five cross-script globals; `registryScopeKey` appeared only when the real gate ran over the real tree (a top-level `let` in `objects/registry.js` read by `objects/crossings.js`) and would otherwise have been reported as a false positive on shipped code.
- Evidence honesty: the browser suite proves browser enforcement of the supplied policy for the shipped assets; it does not prove nginx header inheritance on the deployed edge — recorded in `tests/browser/README.md`.
