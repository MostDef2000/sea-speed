# Spec: frontend quality gates — an ESLint no-undef gate and a real six-page browser smoke

- Issue: #684

## Product outcome
Issue #684 closes the evidence gap the quality audit found: two undeclared-identifier bugs passed a fully green CI. `d` in the road page `loadSpeedConfig` and `line` in the `cxOffBtn` re-enable handler are `no-undef` defects, and the existing CSP oracle never exercised the objects page at all, so neither the syntax pass (`node --check`) nor the CSP oracle could see them. This change adds two independent, non-overlapping gates to the `static-contract-security` job of `.github/workflows/quality-integration.yml`: (1) a non-mutating ESLint `no-undef` gate over `frontend/**/*.js` (`npm run lint:js` = `eslint frontend`) with a committed flat config and exact-pinned tooling, and (2) a real headless-browser smoke (`npm run test:browser` = `playwright test`) that loads all six operator pages in Chromium with the production enforcing CSP served as a real response header, asserts every script `src` returns 200, and asserts a page-specific ready condition plus zero uncaught exceptions and zero CSP violations per page. Both gates are reproducible from a committed lockfile with `npm ci --ignore-scripts`, run inside the existing 15-minute job budget, and preserve every existing security check untouched.

## User scenarios
- A developer opens a pull request that re-introduces an undeclared identifier in `frontend/sea-speed/**/*.js`: the `ESLint no-undef (non-mutating)` step fails the `static-contract-security` job with the exact `no-undef` diagnostic, the aggregate `quality-integration` gate fails, and the pull request cannot merge green.
- A developer opens a pull request that breaks a shipped page at runtime (a missing element binding, a script that no longer resolves, a violation of the production CSP): the `Browser smoke (six operator pages)` step fails with the page name attached, so the regression is caught before merge instead of after deploy.
- An operator's page set is covered end-to-end: root (`/`), the sea-speed dashboard (`/sea-speed/`), objects, cameras, road and the unavailable page (`/sea-speed/unavailable.html`) all load in real Chromium from the same fixture server that serves the shipped HTML and every script URL those pages reference, so a page that only the CSP oracle ever saw (objects) can no longer regress silently.
- A maintainer re-runs CI on the same commit: the gate is byte-reproducible — `npm ci --ignore-scripts` installs exactly the locked tool tree (eslint 10.15.0, globals 17.14.0, @playwright/test 1.65.1), Chromium is installed from the pinned Playwright version, retries are 0 and timeouts are bounded (20 s per test, 120 s global), so a red result is a real defect and not a retry artefact.

## Requirements
1. Static gate: `eslint.config.mjs` is a flat config over `frontend/**/*.js` with `sourceType: "script"`, `no-undef: error`, the `globals.browser` set plus exactly five documented cross-script globals — `SeaSpeedOverlayCanvas`, `SeaSpeedAuth`, `SeaSpeedLiveSync`, `Hls` and `registryScopeKey`; `registryScopeKey` is a top-level `let` in `frontend/sea-speed/objects/registry.js` read by `frontend/sea-speed/objects/crossings.js`, discovered during implementation, and without it the gate would emit a false positive.
2. Untouched frontend: no file under `frontend/**` is edited by this change; the gate must report zero diagnostics on the current tree exactly as shipped.
3. Historical RED proof: on revision `30773ae` the same gate reports exactly the two historical bugs and nothing else — `'line' is not defined.` once and `'d' is not defined.` twice (`git show 30773ae:frontend/sea-speed/road/main.js` piped through `eslint --stdin --stdin-filename frontend/sea-speed/road/main.js --format json` → rc=1, 3 `no-undef` diagnostics at lines 69 and 71 of the historical file).
4. Browser smoke: `playwright.config.mjs` is Chromium-only, `testDir: ./tests/browser`, `retries: 0`, `timeout` 20 s per test, global timeout 120 s, `baseURL http://127.0.0.1:8131`, and no `webServer` block (the fixture server is started by the suite itself so the served policy and fixtures are explicit).
5. Six-page coverage: `tests/browser/fixture-server.mjs` serves the six real operator pages and every script URL those pages reference with the production enforcing CSP as a real response header and deterministic API/session fixtures; the CDN `hls.js` tag is intercepted by `page.route` and fulfilled by a local stub, and the fixture strips only that one tag's SRI/`crossorigin` attributes because a synthetic stub cannot match the pinned digest — the strip is documented and asserted, not silent.
6. Browser assertions: `tests/browser/operator-pages.spec.mjs` holds 8 tests — one per operator page plus an hls-stub proof and a CSP-enforcement proof; every page test asserts the exact CSP response header, that every script `src` returned 200, a page-specific readiness condition, and zero uncaught exceptions and zero CSP violations.
7. Road and Objects depth: the road page check asserts the crossings stats table (`#cxStatsRows`) and that the period date control is populated with Vladivostok today (`#cxFrom` non-empty), and the objects page check asserts the domain selector value (`#domainInput` = `water`) and the registry grid's rendered state (`#objectsGrid`) — neither page is asserted by a bare `document.readyState` probe.
8. Honest evidence scope: `tests/browser/README.md` states the limit explicitly — the suite proves browser enforcement of the supplied policy for the shipped assets, NOT deployed nginx header inheritance.
9. Reproducible CI wiring: `package.json` pins eslint 10.15.0, globals 17.14.0 and @playwright/test 1.65.1 exactly, `package-lock.json` is committed, `.gitignore` covers `node_modules/`, `playwright-report/` and `test-results/`, and the four steps (`npm ci --ignore-scripts`, `npm run lint:js`, `npx playwright install --with-deps chromium`, `npm run test:browser`) run in `static-contract-security` immediately after the SHA-pinned `Set up Node.js` step.
10. Preserved surface: triggers, permissions, job topology, the 15-minute timeout, the aggregate `quality-integration` logic and every pre-existing step stay byte-identical; no step is added to `pr-validation.yml` or any other workflow; the Python battery, validators and ruff stay green.

## Acceptance criteria
- AC-001: on revision `30773ae` the static gate reports exactly the two historical bugs (3 `no-undef` diagnostics: `line` once, `d` twice, rc=1), and on the current frontend it reports zero diagnostics with rc=0.
- AC-002: all six operator pages load in real Chromium with the production CSP enforced, every script `src` returns 200, and each page reaches its page-specific ready condition with no uncaught exception and no CSP violation.
- AC-003: the Road and Objects checks are real interaction/readiness checks — road crossings stats table (`#cxStatsRows`) plus a populated Vladivostok-today period control (`#cxFrom`), objects domain selector (`#domainInput` = `water`) plus the registry grid (`#objectsGrid`) — not bare load probes.
- AC-004: CI is reproducible with exact-pinned tooling and a committed lockfile (`npm ci --ignore-scripts`), bounded timeouts (20 s per test, 120 s global, retries 0, no silent skips) and the existing security checks are preserved.

## Runtime feedback
- Two undeclared-identifier bugs shipped through green CI: `d` in `frontend/sea-speed/road/main.js` `loadSpeedConfig` and `line` in the `cxOffBtn` re-enable handler — both are pure `no-undef` defects that `node --check` cannot see (it validates syntax, not bindings) and the CSP oracle never evaluated.
- The CSP oracle covered five pages and silently skipped objects, so a page-level regression on objects had no automated signal at all; the new smoke asserts the page set explicitly (six pages + stub + CSP proof = 8 tests).
- Implementation feedback: the flat config needed the `globals.browser` set plus five cross-script globals; `registryScopeKey` surfaced only when the real gate ran against the real tree and would otherwise have been a false positive on objects/crossings.js.
