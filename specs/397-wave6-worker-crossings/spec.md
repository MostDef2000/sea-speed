## Product outcome

Waves 1-5 extracted the pure kernel (#475), the media/reader layer (#476), the cv2 render/snapshot layer (#479) and the requests transport/posting layer (waves 4-5); the worker still mixes the crossing analytics domain with the ROI cluster, the live-publisher loop, the speed-lines domain and the supervision main loop. Wave 6 extracts the crossing-domain cluster verbatim (move-only, byte-identical bodies) into NEW `worker/worker_crossings.py`: the 5 state literals (`_crossing_track_sides`, `_crossing_counts`, `_crossings_by_class`, `VLZ_TIMEZONE`, `_crossing_vlz_date`) and the 6 defs (`vlz_date`, `reset_crossing_counts`, `maybe_reset_daily_crossings`, `prune_crossing_tracks`, `update_crossing_counts`, `crossing_overlay_summary`) — ONE contiguous region (worker 544-664 at main 854b08f) cut bottom-up with the standing blank-pair discipline.

The wave's central mechanism is the OBJECT-IDENTITY coupling with worker_transport: `_crossing_line_cache` and `_crossing_pending_posts` are transport-OWNED objects (their defining literals stay in worker_transport.py from waves 4-5); worker_crossings imports them and every access is an in-place mutation (`.clear`/`.append`) or a read — nothing in the new module rebinds them, so the wave-4/5 identity contract holds unchanged and `worker._crossing_pending_posts` remains ONE list object shared by the transport mover (`flush_crossing_posts`) and the crossing mutators (now in worker_crossings). `_crossing_vlz_date` moves WITH its sole rebinder `maybe_reset_daily_crossings` (the only `ast.Global` naming it sits in that def) — the pair is never split. The state names are NOT re-exported: the worker has zero staying readers of them (verified by grep + AST sweep at 854b08f); the 6 def names ARE re-exported via a second flat sibling ImportFrom (allowed: the transport pin filters `node.module == "worker_transport"` only), keeping main()/staying-caller global-name resolution, the ns-injection surface and the `globals()`-guard call site in `build_road_live_envelope` intact.

Deliberate STAYS in the worker (recorded, not silently dropped, with forced reasons):
- `_roi_processing_points`, `prepare_roi_processing_frame`, `detection_inside_road_roi`, `roi_processing_signature`, `draw_roi_polygon`, `parse_road_roi_polygon`, `road_roi_enabled` — the ROI family: `_roi_processing_points` REBINDS via `global` + assignment (worker:349 pre-cut → 366/377 post-cut) which a moved rebinding name cannot satisfy, and the family's callees are cv2/numpy (off the crossings import allowlist by construction).
- `_LIVE_PUBLISH_QUEUE`, `_LIVE_PUBLISH_LOCK`, `_LIVE_PUBLISH_THREAD` + `_live_publisher_loop`, `_ensure_live_publisher`, `post_live_envelope` — the live-publisher family: `threading`/`queue` are off the crossings allowlist and `_LIVE_PUBLISH_THREAD` REBINDS (worker:459/462 pre-cut → 476/479 post-cut) inside `_ensure_live_publisher`; only the loop's network body moved in wave 5.
- `_line_speed_state` + `update_speed_lines_estimate` — the speed-lines analytics domain: the state's sole consumer stays (staying mutator reading `fetch_speed_lines_config` through the re-export).
- `detect_vehicles`, `build_road_live_envelope`/`build_water_live_envelope`, `main` and the track/event pipeline — the supervision main loop and its callees (cv2/numpy/ultralytics domain) are outside the crossing cut.

Convergence is fail-closed everywhere the new deployable ships: the compatibility gate's `MODULE_SOURCES` extends 4→5 (five-file union, semantics unchanged), `validate_repo` REQUIRED_FILES, `build_exact_artifacts` (ubuntu-worker AND edge), `validate_exact_artifacts` (ubuntu-worker AND edge) and the installer's prepared-release required loop all gain `worker/worker_crossings.py`, so a payload missing the flat sibling fails at CI or install — never silently at boot. One dead import (`from datetime import datetime, timedelta, timezone` in the worker) is removed as a forced consequence of the cut: the sole uses (worker:547/554/641 pre-cut) all moved; ruff F401 would fail CI otherwise.
