## Architecture

- worker_crossings.py: the crossing analytics domain over the transport — 5 state literals + 6 defs in source order. Imports: time/datetime + worker_kernel (env_float, side_of_line, sign_with_deadzone) + worker_transport (_crossing_line_cache, _crossing_pending_posts, fetch_crossing_line_config). NO cv2/numpy, NO ultralytics/av, NO subprocess/socket, NO threading/queue, NO requests/json/pathlib/os.
- Object-identity coupling: `_crossing_line_cache`/`_crossing_pending_posts` remain DEFINED in worker_transport (waves 4-5); worker_crossings imports the objects and mutates them in place (`.clear` in reset_crossing_counts, `.append` in update_crossing_counts, `.get` reads in crossing_overlay_summary). The worker keeps re-exporting `_crossing_pending_posts` (identity pin green) even though the worker itself no longer mutates it — the transport mover and the crossings mutators share ONE list.
- Rebinder coupling: `_crossing_vlz_date` (module-level `None` literal) + `maybe_reset_daily_crossings` (the only `global` statement naming it) moved together under the same module top level; the daily-reset flow (`maybe_reset_daily_crossings` → `vlz_date` → `reset_crossing_counts`) is self-contained in worker_crossings.
- hls_motion_yolo_worker_events.py: keeps ROI family, live-publisher family, speed-lines domain, track/event pipeline and main. Staying callers of moved helpers resolve via the second flat sibling re-export: `main` → `update_crossing_counts`; `build_road_live_envelope` (globals()-guard) and `main` → `crossing_overlay_summary`. Import cycle safety: worker_crossings imports worker_kernel + worker_transport (never the worker — chain crossings→transport→media→kernel acyclic); the new re-export block sits after the transport block, before first use.
- Gate scan model: MODULE_SOURCES extends to the FIVE-file union (worker + media + render + transport + crossings); REQUIRED_ENV_NAMES unchanged — the cluster reads only DETECTION_TRACK_MAX_GAP_SEC/CROSSING_MIN_INTERVAL_SEC via env_float (not required); the union scan keeps every required env read covered.

## Decisions

- D-1: Verbatim byte-level move (assertion-guarded script, single contiguous region 544-664) instead of retyping: guarantees byte- and AST-identity, verified programmatically after the write against `git show 854b08f` (region byte-identical; 11/11 names AST-identical; moved names gone from worker; zero duplicate defs).
- D-2: A SECOND ImportFrom (module worker_crossings) is allowed: the wave-4 transport pin filters `node.module == "worker_transport"` only, so the exactly-one assertion is per-module; the new block carries the 6 def names sorted, state names excluded (no staying reader — verified zero uses outside the region at 854b08f).
- D-3: `_crossing_vlz_date` moves WITH its sole rebinder `maybe_reset_daily_crossings` (never split): a rebinding name cannot move away from its rebinder without changing semantics; the AST no-rebinding guard covers the other 4 state names, and the rebinder-coupling pin (test (d)) freezes the pairing (exactly one Assign beyond the literal; enclosing FunctionDef; sole ast.Global; both top-level in worker_crossings).
- D-4: The recorded STAYS are forced, not stylistic: the ROI family stays because `_roi_processing_points` rebinds (worker:349 pre-cut) and its callees are cv2/numpy; the live-publisher family stays because threading/queue are off-allowlist and `_LIVE_PUBLISH_THREAD` rebinds (worker:459/462 pre-cut); `_line_speed_state` + `update_speed_lines_estimate` stay (speed-lines analytics domain, sole consumer); `detect_vehicles`/`main` and the track/event pipeline stay (model/cv2 domain + supervision loop).
- D-5: One dead `from datetime import datetime, timedelta, timezone` is removed from the worker as part of the cut (forced deviation): the sole uses (worker:547/554/641 pre-cut) all moved; grep + AST sweep confirm zero remaining `datetime` references in the worker; ruff F401 would fail CI otherwise; the gate's union scan does not pin datetime in the worker file. `import json` STAYS (still used at the water-recall diagnostic).
- D-6: NO monkeypatch-target transfers and NO #398 pin edits this wave: the ns-injection fakes (test_line_crossing extract_worker_functions pattern) are exec-based and location-independent — the harness resolves moved defs from worker_crossings (first-definition-wins across the SIX sources) and injected fakes replace bare names in the exec namespace; test_line_crossing.py needs NO edits (verified by run).
- D-7: validate_sdd GRANDFATHERED_PREFIX_COLLISIONS "397" gains the wave-6 dir — the scheduled exact-set break continuing the 396/waves-1-5 pattern.
- D-8: The transport test's no-rebinding scan extends to the crossings file: the loop's purpose is scanning every file where moved-cache names may appear; the crossings module now hosts the in-place mutators, so a future rebinding there (e.g. `_crossing_pending_posts = []` in reset_crossing_counts) must fail CI exactly as it would in the worker.
